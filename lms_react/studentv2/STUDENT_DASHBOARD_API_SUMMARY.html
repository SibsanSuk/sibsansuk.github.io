1. Executive summary

Student Dashboard ใช้ courseid จาก URL และข้อมูลผู้เรียนจาก OIDC เพื่อเชื่อมข้อมูลจาก SBS, BookRoll, Video, Chatbot, VK และ Adaptive Quiz โดย Course Tree เป็น gatekeeper ของการโหลดข้อมูลทั้งหมด

สาระสำคัญที่สุด: ค่า Overall progress ปัจจุบันคำนวณจาก BookRoll และ Video เท่านั้น ส่วนคะแนน Chatbot และข้อมูล VK แสดงผลประกอบ แต่ยังไม่ถูกรวมในเปอร์เซ็นต์ความคืบหน้ารวม
  1. ระบบต้อง login ด้วย OIDC Authorization Code + PKCE เพื่อได้ profile, email และ access token
  2. Frontend เรียก SBS Course Tree ก่อน เพื่อทราบโครงสร้างรายวิชาและชนิดเครื่องมือที่มี
  3. เมื่อ Course Tree สำเร็จ งาน BookRoll, Video, Chatbot, VK และ Adaptive Quiz จึงเริ่มทำงานแบบขนาน
  4. BookRoll, VK และ Chatbot API เดิมใช้ user ID ที่คาดหวังให้เป็น Keycloak sub
  5. Video, Chatbot API ใหม่ และ Adaptive Quiz ใช้อีเมลจาก OIDC profile
  6. Chatbot ใช้ API ใหม่ก่อน แล้ว fallback ไป API เดิมของ SBS เมื่อไม่มีข้อมูลหรือ API ใหม่มีปัญหา ยกเว้นกรณี 401
  7. VK เรียก course overview หนึ่งครั้ง แล้วเรียก chapter overview เพิ่มตามจำนวนบท
  8. Adaptive Quiz shared dashboard ถูกโหลดและเก็บเป็น raw data แต่ยังไม่เชื่อมเข้ากราฟหลัก

5. รายละเอียดตามระบบ

5.1 OIDC — Login, profile และ session

Client ID: dashboard  •  Scope: openid profile email  •  Flow: PKCE S256

Redirect URI คือ URL หน้าปัจจุบันหลังตัด query string และ hash ออก ระบบเก็บ PKCE verifier และ auth payload ใน sessionStorage หลังแลก code แล้วจะเรียก userinfo เพื่อหา profile และ user ID

GET /openid-connect/auth
POST /openid-connect/token
GET /openid-connect/userinfo
GET /openid-connect/logout

ถ้า access token หมดอายุตาม JWT exp หรือ API ที่ตรวจ session ตอบ 401 ระบบจะล้าง auth และแสดง session-expired overlay

5.2 SBS Course Tree — Dependency หลัก

GET https://sbs-backend.mooc.meca.in.th/lms/{urlEncodedCourseId}

Frontend ใช้ courseTitle/title, courseKey/course_key และ tree chapter → sequential → vertical → children เพื่อสร้างหัวข้อการเรียน, จำแนก AE Tool และหา Adaptive Quiz refCode

ผลลัพธ์ถูกเก็บใน window.courseDetailData และสร้าง window.courseToolInventory สำหรับ BookRoll, Video, Chatbot และ VK

5.3 BookRoll — Reading progress

GET https://bookroll.thaidlt.com/meca/student/readingData
?userID={userId}&usageId={courseId}&view=student&ts={timestamp}
  • เรียกหนึ่งครั้งต่อรอบโหลด dashboard ไม่ fan-out ราย block
  • ts ใช้ cache busting
  • รองรับ response แบบ array, object map และค่า read:total เช่น 7:10
  • Frontend normalize เป็น title, usageId, read, total และ progress 0–100
  • จับคู่กับ course tree ด้วยชื่อก่อน แล้วจึงลอง usage/block ID

5.4 Video — Progress และ Heatmap

GET https://viola.thaidlt.com/meca/chart/bar/?userName={email}&usageId={courseId}
GET https://viola.thaidlt.com/meca/chart/heatmapTime/?userName={email}&usageId={courseId}
  • bar เป็นข้อมูลหลัก: category จาก yAxis.data และ progress จาก series[0].data
  • heatmapTime เป็นข้อมูลเสริม: ช่วงเวลาจาก xAxis.data และ event จาก [xIndex,yIndex,count]
  • ถ้า bar ล้มเหลว task Video เป็น error; ถ้า heatmap ล้มเหลวแต่ bar สำเร็จ task ยังถือว่าสำเร็จ
  • จับคู่ item ด้วยชื่อ และมี fallback ตามลำดับวิดีโอใน course tree

5.5 Chatbot — API ใหม่และ fallback

Source priority: Profile API ใหม่ → ถ้ามี Quiz ที่เคยทำให้ใช้ทันที → ถ้าไม่มีข้อมูลหรือเกิด error ให้ fallback ไป SBS speed + performance → ถ้าตอบ 401 ให้จบ task และแสดง session expired โดยไม่ fallback

API ใหม่

GET {PROFILE_BASE}/api/kidbright/course/{courseId}/data/chatbot?email={learnerEmail}
Authorization: Bearer {accessToken}

Base URL ปริยายคือ https://adaptive-profile-bn.ae.app.meca.in.th และเปลี่ยนได้ผ่าน STUDENT_DASHBOARD_CONFIG.baseUrl

Frontend ใช้เฉพาะ Quiz ที่เคยเริ่มทำ โดยดูจากจำนวน attempt, attempt history หรือ first/last attempt timestamp ข้อมูลที่ใช้ประกอบด้วยคะแนนผู้เรียน, คะแนนเฉลี่ยของกลุ่ม, เวลา, attempts, percentile และ completion

API เดิมจาก SBS

GET SBS /stats/echart/chatbotSpeed/{courseId}/{userId}
GET SBS /stats/echart/chatbotPerformance/{courseId}/{userId}

สอง endpoint ถูกเรียกพร้อมกันและเป็นอิสระต่อกัน หากอย่างน้อยหนึ่ง endpoint สำเร็จ task Chatbot ยังถือว่าสำเร็จ Response รองรับ ECharts config ที่ root หรืออยู่ใต้ chart

Debug endpoint

GET SBS /me/data/chatbot/{courseId}
Authorization: Bearer {accessToken}

เรียกเฉพาะเมื่อ URL มี debug=1 และรายวิชามี Chatbot ข้อมูลแสดงใน debug card เท่านั้น ไม่ถูกนำไปคำนวณ dashboard หลัก

5.6 VK Analysis — Course overview + Chapter fan-out

GET {VK_BASE}/analysis/overview/{userId}/course/{courseId}
GET {VK_BASE}/analysis/overview/{userId}/course/{courseId}/chapter/{chapterNo}
  1. เรียก course overview และอ่านเลขบทจาก Params.x_data
  2. ตัดค่าซ้ำและใช้เฉพาะเลขที่มากกว่า 0
  3. เรียก chapter overview ทุกบทพร้อมกัน
  4. หากบางบทล้มเหลว บทอื่นยังใช้ได้และ task โดยรวมยังถือว่าสำเร็จ

Frontend ใช้ Params.x_data, Params.series, x_locate, x_title และ VK skill.series.Result เพื่อแสดง activity, metric และ skill result

5.7 Adaptive Quiz Shared Dashboard

GET edubot.abdul.in.th/adaptive-quiz/api/v1/shared-dashboard/learner/{email}/by-lead-label/{leadLabel}?ref_code={refCode}
x-api-key: {readOnlyApiKey}

leadLabel คือ Course ID หลังตัด course-v1: ส่วน refCode มาจาก runtime config, query string หรือ Adaptive Quiz block ใน course tree

Response ถูกเก็บใน window.adaptiveQuizSharedDashboardRaw และใช้สรุปจำนวน collection/quiz ใน debug status แต่ยังไม่เชื่อมเข้ากราฟหลัก

Security: โค้ดปัจจุบันฝัง Adaptive Quiz read-only API key ใน browser bundle ผู้ใช้จึงสามารถดูคีย์ได้ ควร rotate คีย์เดิมและย้าย request ผ่าน backend หรือ serverless proxy ที่ตรวจสิทธิ์

สูตรรวม: ค่าเฉลี่ยเลขคณิตของ progress ทุก vertical ที่มีค่าในทุกบท
  • Vertical ที่มีหลาย subtool จะเฉลี่ยเฉพาะ subtool ที่มี progress เป็นตัวเลขก่อน
  • ทุก vertical มีน้ำหนักเท่ากัน ไม่ถ่วงตามจำนวนหน้า ระยะเวลาวิดีโอ จำนวน Quiz หรือจำนวนบท
  • รายการที่ไม่มีข้อมูลถูกตัดออกจากตัวหาร ไม่ได้นับเป็น 0
  • กิจกรรมลงทะเบียนหรือ profile AE Tool ให้ progress เป็น null
  • สถานะ: 100% = เสร็จ, มากกว่า 0 = กำลังทำ, 0 = ยังไม่เริ่ม, ไม่มีตัวเลข = ไม่มีข้อมูล

7. Error, Retry และ Debug behavior

  • แต่ละ task มีสถานะ pending, requesting, success, error หรือ skipped
  • ไม่มี automatic retry; ผู้ใช้ retry เฉพาะ task หรือ retry รายการที่ล้มเหลวทั้งหมดได้
  • Retry Course จะเริ่มรอบโหลด dashboard ใหม่ทั้งชุด
  • ไม่มี request timeout หรือ AbortController; request ที่ค้างอาจทำให้ loading อยู่ในสถานะ requesting นาน
  • เปิด debug card ด้วย debug=1
  • เปิดปุ่ม Login/Logout ด้วย loginbtn=true; ค่า default ซ่อนปุ่มและ redirect ไป login อัตโนมัติเมื่อไม่มี session

☐ Token หมดอายุแสดง session-expired overlay และ login ใหม่ได้

☐ วิชาที่มีเฉพาะ BookRoll เรียก BookRoll หนึ่งครั้ง และไม่เรียก Video/Chatbot/VK

☐ Chatbot API ใหม่มีข้อมูลแล้วไม่เรียก SBS legacy

☐ Chatbot API ใหม่ไม่มี attempt แล้ว fallback ไป speed/performance
