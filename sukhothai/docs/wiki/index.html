Phase Journey (Gamify)

เลือก phase ปัจจุบัน แล้วทำตามลำดับเควสต์เพื่อเดินงาน MVP ให้ไม่หลุด scope

เป้าหมาย: ออกแบบ data model หลักของ MVP ให้ครบก่อนเริ่ม command layer

  1. ออกแบบข้อมูลระบบแผนที่ (tile/zone/river/canal/walkability/placement constraints)
  2. ออกแบบ data ของ building, resource, character/agent และความสัมพันธ์กัน
  3. ล็อก schema/key naming ที่ใช้ร่วมกัน และอัปเดตรายการ P0 ที่เกี่ยวข้อง
Technical Design Content Registry MVP Summary Architecture Decisions
  • map/building/resource/character data model ระบุชัดเจน
  • placement rules ขั้นต่ำและ coverage assumptions ล็อกแล้ว
  • รายการ P0 ฝั่ง data design ถูกอัปเดตสถานะใน registry

เป้าหมาย: สร้าง command/event contract บน data model ที่ล็อกแล้ว

  1. นิยาม command หลัก (place/remove/build/assign/speed/pause) พร้อม payload
  2. กำหนด validation rules ให้สอดคล้องกับข้อจำกัดของ map/building/resources
  3. กำหนด event ที่จำเป็นต่อ simulation/HUD และ sync กับเอกสารเทคนิค
Player Commands Content Registry Technical Design
  • command หลักระบุ payload + validation ครบ
  • event contract ที่กระทบ HUD/gameplay ถูกกำหนดชัดเจน
  • เอกสาร command/technical design ไม่ขัดกัน

เป้าหมาย: ทำช่วงเล่นนาที 0-6 ให้จบได้และวัดผลได้

  1. กำหนด objective ช่วงต้นเกมให้ measurable ใน `MVP Summary`
  2. ล็อก coverage model น้ำ/ตลาด/ศรัทธาใน `Content Registry`
  3. ผูก command ที่ต้องใช้กับ tutorial flow ใน `Player Commands`
MVP Summary Content Registry Player Commands
  • objective ทดสอบซ้ำได้ด้วยตัวเลข/เงื่อนไขชัดเจน
  • coverage model ล็อกและไม่มีจุดขัดแย้งเอกสาร
  • tutorial steps จำเป็นถูกระบุครบ

เป้าหมาย: ล็อกวิกฤตหลัก 1 แบบ และ win/lose condition ที่เทสต์ได้จริง

  1. ตัดสินใจวิกฤตหลัก (`flood` หรือ `drought`) ใน `Architecture Decisions`
  2. ระบุ impact modifiers และ phase วิกฤตใน `Technical Design`
  3. อัปเดตเงื่อนไขชนะ/แพ้ใน `MVP Summary` และ `Content Registry`
Architecture Decisions Technical Design MVP Summary Content Registry
  • วิกฤตหลักถูกตัดสินใจชัดเจน 1 แบบ
  • impact modifiers ระบุชัดและ trace ได้
  • win/lose checks เป็นเกณฑ์ตัวเลขที่เทสต์ซ้ำได้

เป้าหมาย: ปิดงานให้พร้อมเดโมและพร้อมรับ feedback จาก playtest

  1. ล็อก status สุดท้ายของทุก P0/P1 ใน `Content Registry`
  2. เช็กความพร้อมรอบส่งมอบด้วย `Execution Checklist`
  3. จัดโน้ตส่งต่อรอบถัดไปใน `Handoff Guide`
Content Registry Execution Checklist Handoff Guide
  • playtest script พร้อมใช้งาน
  • KPI ที่ใช้ประเมินผลล็อกแล้ว
  • known issues ระบุความเสี่ยงและลำดับแก้ไข
